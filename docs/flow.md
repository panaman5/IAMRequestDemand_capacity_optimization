# Modeling flow

## Demand and workload

Historical IAM events are transformed into request observations. Each request
gets a continuous workload weight from its active backend tasks, capacity
units, workflow overhead, and approval outcome. No fixed business request
taxonomy is required.

The time-bucket aggregate is:

```text
W_t = sum_i(w_i,t)
```

## Forecast composition

The forecast is composed of three signals:

```text
N_t                 request count
p_reject,t          rejection probability
F_A(w), F_R(w)      workload distributions by outcome
```

The predictive total is generated by sampling a count, sampling an outcome for
each request, sampling its weight from the corresponding distribution, and
summing the weights.

## Capacity decision

Let `C_total,t` be the total capacity available in the same time bucket and
capacity units as `W_t`. Protect a selected workload quantile:

```text
C_requests,t = Q95(W_t)
C_spare,t    = max(0, C_total,t - C_requests,t)
C_deficit,t  = max(0, C_requests,t - C_total,t)
```

Requests have priority by construction. Other objects are eligible only for
`C_spare,t`.

## Continuous update

When a new time bucket closes:

1. update the latent request-demand state from the request-count forecast error;
2. update the rejection state from the approval decision error;
3. add completed request weights to the recent-data-weighted empirical
   distributions;
4. use the updated components for the next forecast.

The future queue model will consume the resulting workload distribution and
calculate backlog and service-level outcomes when capacity is insufficient.
